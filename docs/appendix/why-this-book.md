# Зачем нужна эта книга

Материалов про AI-агентов уже много.

Гораздо реже встречаются материалы, которые рассматривают агентные системы как то, что нужно эксплуатировать, контролировать, ревьюить и развивать в условиях реального production.

Эта книга нужна, чтобы закрыть именно этот разрыв.

## Чем эта книга не является

Это не:

- manual по фреймворку
- гайд по vendor-продукту
- коллекция промптов
- экскурсия по benchmark leaderboard
- общий эссеистический текст про AI-тренды

Все эти материалы могут быть полезны. Но обычно они закрывают только часть задачи.

## Что эта книга пытается сделать

Этот проект рассматривает агентные системы как операционные системы, у которых должны быть:

- границы доверия
- выполнение под контролем политик
- маршруты подтверждения для рискованных действий
- дисциплина памяти
- наблюдаемость и evals
- контроль раскатки и управление жизненным циклом

В этом и состоит главное отличие.

## В сравнении с документацией фреймворков

Документация фреймворков полезна, когда ты уже понимаешь, какую систему хочешь собрать.

Обычно она хорошо помогает с:

- паттернами orchestration
- графами состояний
- подключением инструментов
- деталями реализации

Но она часто не отвечает на более трудные вопросы:

- Что вообще должно быть разрешено?
- Какие действия требуют подтверждения?
- Как ограничивать память?
- Как безопасно раскатывать изменения?
- Как проводить аудит после инцидентов?

Эта книга должна стоять над фреймворками, а не заменять их.

## В сравнении с vendor docs

Vendor docs часто дают самый короткий путь к демо.

Обычно они сильны в:

- model-specific возможностях
- использовании SDK
- platform integrations
- продуктовых примерах

Но они естественным образом ограничены поверхностью конкретного вендора.

Эта книга пытается оставаться vendor-neutral и architecture-first.

## В сравнении с security checklist-подходом

Security guidance необходима, но одних чеклистов недостаточно, чтобы получить рабочую архитектуру агентной системы.

Чеклисты говорят, на что смотреть. Но они не всегда объясняют, как построить runtime, ownership, approvals, telemetry и lifecycle так, чтобы риски оставались ограниченными со временем.

Эта книга пытается связать security concerns с конкретным runtime design.

## В сравнении с cloud reference architectures

Cloud blueprints хорошо показывают deployment shape.

Но многим командам нужны ответы на другом уровне:

- что должно принадлежать policy layer
- как должен работать approval
- что нужно трассировать
- как оценивать behavioral regressions
- как не допустить agent sprawl

Эта книга сфокусирована именно на этом операционном слое.

## Какой результат задуман

Цель не в том, чтобы помочь построить самого автономного агента.

Цель в том, чтобы помочь построить агентную систему, которая:

- полезна
- объяснима
- пригодна для ревью
- управляема
- пригодна для production

Если тебе это интереснее, чем agent theater, значит книга написана для тебя.
