# Дорожная карта для сообщества

Если смотреть на книгу глазами читателя из любой страны, у нее уже есть сильная база: архитектура, безопасность, память, выполнение, наблюдаемость, организационная модель и эталонный пакет. Но чтобы проект действительно притягивал сообщество, ему нужен следующий слой: **быстро применимая польза**.

Ниже собран практический backlog из 10 шагов. Это не абстрактные пожелания, а конкретные улучшения, которые делают книгу полезнее для инженеров, платформенных команд, security-специалистов и open source контрибьюторов.

## Принцип отбора

Каждый пункт ниже проходит по трем критериям:

- его можно быстро применить в реальной работе;
- он полезен не только автору книги, но и внешнему сообществу;
- он повышает международную читаемость проекта, а не только глубину текста.

## Топ-10 улучшений

### 1. Страница `Start here`

Нужна короткая входная страница для новых читателей:

- что это за книга;
- для кого она;
- с каких глав начинать инженеру;
- с каких глав начинать security-команде;
- где лежат готовые шаблоны и код.

Почему это важно: большинство новых читателей не начинают с главы 1. Они хотят быстро понять, где их маршрут.

### 2. Многоязычный глоссарий

Нужен словарь ключевых терминов в `ru/en/zh`:

- agent runtime;
- policy gate;
- trust boundary;
- profile memory;
- retrieval;
- compaction;
- rollout gate;
- capability catalog.

Почему это важно: сейчас терминология в книге уже неплохая, но глоссарий сильно упростит чтение, переводы, ссылки и вклад сообщества.

### 3. Cheat sheets на одну страницу

Нужны короткие практические шпаргалки:

- safety checklist;
- memory checklist;
- rollout checklist;
- observability checklist;
- tool gateway checklist.

Почему это важно: такие страницы люди реально сохраняют, пересылают коллегам и используют в работе в тот же день.

### 4. Набор case studies

Нужно добавить 3-5 коротких реальных сценариев:

- support agent;
- internal knowledge agent;
- enterprise workflow agent;
- CRM/task agent;
- security-sensitive assistant.

Почему это важно: кейсы помогают читателю узнать себя и понять, как применять архитектуру вне абстракций.

### 5. Готовые policy templates

В книге уже есть примеры, но сообществу нужны более явные шаблоны:

- tool approval policy;
- memory write policy;
- egress policy;
- rollout gate policy;
- retrieval policy.

Почему это важно: шаблон, который можно взять и адаптировать, ценнее длинного текста о том, почему шаблон нужен.

### 6. Trace schema и event catalog

Нужна отдельная reference-page по telemetry:

- какие event types есть;
- какие поля обязательны;
- как выглядит `trace_id`;
- какие spans считать базовыми;
- что нельзя писать в events.

Почему это важно: observability становится сильнее, когда у сообщества есть общий каркас событий, а не только общая идея.

### 7. Расширение `agent_runtime_ref` реальными сценариями

Пакет уже полезен, но следующим шагом стоит добавить:

- один knowledge scenario;
- один high-risk scenario с approval;
- один denied-by-policy scenario;
- примеры JSONL traces в docs.

Почему это важно: runnable reference package должен быть не просто демонстрацией happy path, а учебным набором production-like сценариев.

### 8. Contribution набор для сообщества

Нужно облегчить внешний вклад:

- страница `How to contribute patterns`;
- шаблон для нового case study;
- шаблон для нового glossary entry;
- шаблон для нового policy template.

Почему это важно: хороший open handbook растет быстрее, когда у людей есть понятный формат, как именно помогать проекту.

### 9. Усиление главной страницы

Главная уже сильная, но ее можно сделать еще полезнее для первого визита:

- отдельный блок “Для кого эта книга”;
- отдельный блок “Что ты унесешь за 30 минут”;
- отдельный блок “What makes this different”.

Почему это важно: мировой охват начинается не с глубины книги, а с того, насколько быстро человек понимает ее ценность.

### 10. SEO и discoverability слой

Нужен системный слой discoverability:

- `Start here`;
- glossary;
- cheatsheets;
- более явные internal links между главами;
- social preview assets;
- structured landing copy для `ru/en/zh`.

Почему это важно: даже сильная книга не работает на сообщество, если ее трудно найти, понять и переслать другим.

## Что делать первым

Если выбирать только ближайшие 3 шага, я бы делал так:

1. `Start here`
2. Glossary
3. Cheat sheets

Это даст самый быстрый рост пользы для сообщества и не потребует переписывать архитектурные главы.

## Что даст наибольший эффект через месяц

Если довести backlog до следующего уровня, то через месяц у проекта появятся:

- более понятный вход для новых читателей;
- больше цитируемых страниц;
- больше reusable материалов для команд;
- более ясный формат внешнего вклада;
- более сильный международный профиль проекта.
