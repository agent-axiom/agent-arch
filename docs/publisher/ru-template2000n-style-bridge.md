## 1. Что это за файл

`Template2000n.dot` - старый бинарный шаблон Microsoft Word:

- формат: `Composite Document File V2 Document`;
- приложение: Microsoft Word 9.0 / Word 2000;
- кодовая страница: 1251;
- исходный шаблон: `Template2000.dot`;
- размер: 107008 bytes;
- содержит VBA-модули и макросы.

Вывод для текущего процесса: этот файл не нужно применять напрямую к Google Doc во время смыслового наполнения рукописи. Google Doc остается рабочей рукописью и source-to-print staging surface. Шаблон нужен позже, на DOCX/export этапе, когда будет смысловая полнота и можно будет делать издательскую нормализацию стилей.

## 3. Безопасность и ограничения

Шаблон содержит VBA-проект. До отдельного решения издательства макросы не запускать автоматически.

Ограничения:

- Google Docs не является нативной средой для `.dot`/VBA-шаблонов;
- прямое применение шаблона к live Google Doc может привести к потере структуры или непредсказуемой конвертации;
- старый бинарный `.dot` лучше использовать как стиль-источник для финального DOCX, а не как текущий рабочий формат;
- проверку результата нужно делать через экспорт в `.docx`, применение/маппинг стилей и визуальный render QA.

## 5. Что нужно сохранять уже сейчас в Google Doc

Чтобы будущая стилизация прошла без ручного восстановления структуры, в Google Doc нужно сохранять не внешнюю верстку, а логическую разметку:

- реальные уровни заголовков, а не жирные строки;
- отдельные блоки кода, даже если пока они выглядят как обычный текст;
- явные подписи к рисункам и таблицам;
- явные callout-заголовки: `Практикум`, `Checklist`, `Что проверить`, `Типичные ошибки`;
- ссылки и источники отдельными блоками, не смешанными с основным текстом;
- термины и определения в устойчивой форме, пригодной для стиля `Definition`;
- отсутствие ручных декоративных решений, которые потом придется снимать.

## 6. Рекомендованный порядок применения

1. Довести смысловой объем рукописи в Google Doc.
2. Экспортировать Google Doc в `.docx`.
3. Создать рабочую копию DOCX.
4. В Word или контролируемом OOXML-процессе применить стиль-mapping из этого bridge.
5. Не запускать макросы шаблона без отдельного ручного решения.
6. Проверить титулы, главы, списки, код, таблицы, рисунки, ссылки и определения.
7. Сделать PDF/render QA после применения стилей.
8. Вернуть список проблем в Google Doc только если это смысловые или структурные проблемы, а не чистая верстка.

## 7. Практический вывод для текущей рукописи

На текущем этапе шаблон влияет не на текст, а на дисциплину подготовки текста:

- каждая глава должна иметь устойчивую heading hierarchy;
- практикумы должны быть отдельными разделами;
- checklists должны быть настоящими списками;
- YAML/Python/trace-примеры должны оставаться отдельными блоками;
- таблицы и рисунки должны иметь явные подписи;
- приложения должны быть структурированы как справочные материалы, а не как продолжение бесконечной главы.

Так рукопись останется удобной для работы в Google Doc, но не станет хаотичной при будущем переводе в издательский DOCX.
