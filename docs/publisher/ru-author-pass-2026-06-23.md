## Статус

Блок "Об авторе" в рукописи есть, но пока остается редакционной заготовкой. Его нельзя закрыть автоматически: биография, публичное позиционирование, ссылки и издательская формулировка должны быть фактически подтверждены автором.

Это корректное состояние для продолжения редакционной подготовки, но не для финальной отправки в издательство.

## Что уже есть в рукописи

В front matter уже есть структура блока:

1. `Об авторе`.
2. `Короткая версия`.
3. `Расширенная версия`.
4. `Факты для заполнения перед публикацией`.

Эта структура пригодна для издательского цикла: короткая версия может пойти в аннотационный пакет, расширенная версия - в книгу или на сайт издательства, список фактов - во внутренний checklist.

## Рекомендуемые форматы заполнения

Короткая версия:

```text
[Публичное имя] - [роль/позиционирование]. Работает с архитектурой агентных систем, инженерными практиками безопасной автоматизации и внедрением ИИ-инструментов в реальные продуктовые и операционные процессы.
```

Расширенная версия:

```text
[Публичное имя] занимается [1-2 области]. В фокусе работы - практический переход от демонстрационных LLM-прототипов к управляемым системам: capability contracts, policy gateway, verifier, observability, rollout, incident response и эксплуатационная ответственность.
```

Факты для издательства:

```text
Роль или должность: [точная публичная формулировка].
Ключевой опыт: [1-2 проверяемые фразы].
Публичные проекты: [проекты, которые можно публично указывать].
Ссылки: [GitHub / сайт / блог / профиль / companion].
Формулировка для издательства: [короткая издательская биография].
```

## Решения, которые должен принять автор

Перед редакционной сдачей автор должен отдельно решить:

- нужна ли благодарность или посвящение;
- какой финальный URL companion указывать в книге;
- какой канал использовать для errata: repository issues, email, site form или отдельная страница;
- можно ли публично связывать книгу с текущим репозиторием `agent-axiom/agent-arch`;
- какие публичные проекты можно упоминать без юридического или корпоративного риска;
- какая биография идет в тело книги, а какая - только в metadata/cover note.

## Редакционное правило

До заполнения автором эти поля не нужно "улучшать" стилистически. Сначала нужны факты, затем редактура формулировок. Иначе легко получить красивый, но неверный блок.
