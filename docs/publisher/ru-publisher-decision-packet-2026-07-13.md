# Пакет решений для финальной подготовки русской рукописи

Дата фиксации: 2026-07-13; структура актуализирована 2026-07-14.

Целевая рукопись:

- Google Doc: <https://docs.google.com/document/d/1LyY2Psy2yaobn7VLmOwLTWm4QVrhp2I-ylE2B7V4pp4/edit>;
- рабочее название: «Архитектура безопасных ИИ-агентов»;
- источник содержания: `docs/book/**`, `docs/appendix/**` и эталонный пакет
  `agent_runtime_ref/**`;
- издательская сборка: `docs/publisher/**`.

Этот документ отделяет инженерно проверяемые действия от решений, которые
должны быть явно подтверждены автором или издательством. До получения ответа
рукопись не сокращается и не перенумеровывается только ради формального
совпадения с исходным планом-проспектом.

## 1. Структура: 28 глав вместо 23

План-проспект содержит 23 главы. Текущая рукопись содержит 28 глав. Расширение
возникло потому, что исходная глава 20 была разделена на шесть самостоятельных
тем:

1. несоответствие целей и внутренний риск;
2. контур заверения и реагирование;
3. цепочка поставки и происхождение артефактов;
4. вывод из эксплуатации;
5. телеметрия обнаружения;
6. реестр и контроль разрастания агентов.

После них исходные главы об эталонной реализации стали главами 26-28.

**Рекомендация:** утвердить структуру из 28 глав. Обратное объединение сделает
главу 20 перегруженной и ухудшит навигацию. Если договор требует отдельного
дополнительного соглашения, использовать приведённое объяснение как основание.

**Нужно подтвердить:** допускается ли структура из 28 глав без изменения
договора или требуется обновлённый план-проспект.

## 2. Формат рукописи: DOCX и Word 97-2003 DOC

Технологические требования называют обязательным формат `.doc`. Рабочий цикл
в Google Docs и контролируемая издательская сборка используют `.docx`, потому
что он сохраняет современную структуру OOXML и позволяет выполнять
автоматические проверки.

**Рекомендация:** передавать два файла:

- проверенный `.docx` как основную редактируемую версию;
- производный `.doc` для формального выполнения технологических требований.

DOC должен быть получен только после финального заполнения авторских полей и
повторно проверен после конвертации. Он не становится новым источником правды.

**Нужно подтвердить:** принимает ли издательство DOCX как основной файл при
наличии дополнительной версии DOC.

## 3. Формат иллюстраций

Технические требования разрешают PNG/TIFF без слоёв и альфа-каналов для
растровых изображений, а для схем перечисляют VSD, CDR, EPS и AI. Рабочий
комплект рукописи хранит PNG и SVG.

**Рекомендация:** передавать для каждой схемы:

- печатный PNG без альфа-канала;
- исходный SVG как редактируемый мастер;
- EPS только после подтверждения издательством, что этот формат нужен для
  конкретной схемы.

Такой комплект не связывает редактирование с устаревшим проприетарным форматом
и одновременно предоставляет готовый растр для текущей вёрстки.

**Нужно подтвердить:** принимает ли издательство SVG вместо VSD/CDR/AI либо
нужен обязательный EPS для каждой схемы.

## 4. Параметры полосы и служебные элементы

Текущая производная Template2000n использует формат Letter и поля 1 дюйм.
Технические требования не фиксируют размер полосы, а сам шаблон не должен
считаться достаточным подтверждением будущего книжного формата.

Проверочный комплект 2026-07-14 содержит 462 страницы в raw-PDF Google Docs и
379 страниц в производной Template2000n. Равенство текстового слоя и
комплектность 54 изображений подтверждены автоматически. Страница 41 raw-PDF
является осознанным переходом на правую полосу; в Template2000n пустых
технических страниц нет. Шаблон запрашивает Times New Roman для основного
текста и Courier New для программных листингов. В headless-проверке
LibreOffice использованы метрически совместимые Liberation Serif и Liberation
Mono; окончательное отображение этих двух шрифтов нужно подтвердить в
издательской версии Microsoft Word.

**Нужно подтвердить:** формат страницы, поля, необходимость авторского
оглавления, колонтитулов и нумерации страниц до передачи в издательство.

До ответа оглавление, колонтитулы и номера страниц добавляются только в
проверочную производную и не считаются окончательной типографской вёрсткой.

## 5. Данные автора и правовые формулировки

Перед финальным экспортом автор заполняет:

1. имя или публичное имя;
2. короткую и расширенную биографию;
3. роль и проверяемый релевантный опыт;
4. публичные ссылки и контакт для издательства;
5. формулировку для обложки или каталога;
6. благодарности либо решение удалить этот пункт;
7. согласованное раскрытие использования ИИ.

Автор и издательство отдельно утверждают подзаголовок, выходные данные,
формулировку отказа от ответственности и текст обложки.

## Критерий закрытия пакета

Пакет считается закрытым, когда четыре издательских решения зафиксированы
письменно, авторские поля заполнены, а итоговые DOCX/DOC и комплект
иллюстраций повторно прошли структурную и визуальную проверку.
