# Часть I. Основания

Первая часть отвечает на вопрос, без которого остальная книга теряет смысл: **что именно ты строишь, когда перестаешь считать агента prompt trick и начинаешь считать его системой**?

Здесь книга делает две вещи. Сначала она объясняет, почему production agent system нельзя мыслить как “LLM плюс несколько tools”. Затем показывает, как выглядит минимально зрелая архитектура, если у системы уже есть право на действие, риск side effects и обязательство переживать инциденты.

!!! info "Короткий маршрут по первой части"
    Если времени мало, пройди этот путь:

    - [Глава 1](chapter-1.md): понять, нужен ли здесь вообще агент, а не обычный workflow;
    - [Глава 2](chapter-2.md): увидеть, как тезис про платформу превращается в архитектуру;
    - [Часть II](../part-ii/index.md): перейти к вопросу, где эта архитектура становится опасной.

## Что ты должен вынести из этой части

- критерии, когда агент вообще нужен, а когда лучше остановиться на workflow;
- критерии выбора между workflow, single-agent loop и более сложной orchestration;
- минимальную схему платформы безопасных агентов;
- язык, на котором можно обсуждать архитектуру с platform, security и product-командами.

## Быстрый self-check

Перед переходом дальше читатель уже должен уметь ответить на четыре вопроса:

- почему здесь вообще нужен агент;
- где у системы живет право на действие;
- какие слои обязательны до первого рискованного write path;
- что должно оставаться single-agent, а что действительно оправдывает split.

Если ответы на эти вопросы пока расплывчаты, к этой части стоит возвращаться как к рабочей рамке, а не только как к введению.
