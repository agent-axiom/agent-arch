# Часть I. Основания

Первая часть отвечает на главный вопрос: как должна выглядеть **современная безопасная архитектура агента**, если ты строишь ее не как игрушку, а как платформенный продукт.

## Что нужно понять перед реализацией

- Агент не равен LLM. LLM только принимает часть решений.
- Безопасность не может быть "обвязкой после MVP". Она должна быть встраиваемой в runtime.
- Большинство production-кейсов выигрывают не от максимальной автономности, а от правильного сочетания `workflow + guarded autonomy`.
- Мультиагентность нужна не "для красоты", а для изоляции контекста, командной ответственности и параллелизма.[^anthropic][^langgraph-multi]

## Итог этой части

К концу первой части у тебя должно сложиться довольно ясное ощущение опоры. В идеале ты унесешь с собой:

- референсную схему платформы безопасных агентов;
- критерии выбора между workflow, single-agent и subagents;
- список обязательных слоев, без которых production-система будет ломкой;
- язык для обсуждения архитектуры с платформенной, security и product-командами.
